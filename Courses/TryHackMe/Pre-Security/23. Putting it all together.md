To summarise, when you request a website, your computer needs to know the server's [[IP address]] it needs to talk to; for this, it uses [[DNS]]. Your computer then talks to the web server using a special set of commands called the [[HTTP]] protocol; the webserver then returns [[HTML]], [[JavaScript]], [[CSS]], Images, etc., which your browser then uses to correctly format and display the website to you.

### Load balancers
When a website's traffic is getting large, or running an app needing high availability, one web server might not be enough. Load balancers provide two main features, ensuring high traffic websites can handle the load, and providing a failover if a server stops working.
When you request a website with load balancer, the load balancer will receive your request first, then forward it to one of the serverS behind it. It uses different algorithms to help it decide which one is the best to deal with the request. 
Example of algorithm : 
- Round-robin: Sends request to each server in turn
- Weighted: Checks how many requests a server deals with and sends it to the least busy server.
They also check periodically if each server runs correctly, it's called a health check. If a server doesn't respond appropriately, or at all, it will stop sending traffic until the server responds appropriately again.

### [[CDN]] (Content delivery networks)
Can be excellent for cutting down traffic to a busy website. Allows you to host static files such as [[Javascript]], [[CSS]], Images, etc... and host them accross thousands of servers.
When a user request one of the files, the CDN finds the nearest server and forwards the request there.
### [[Databases]]
Stores informations for website's users. Webservers can communicate with databases to store and recall data from them. They can range from just a text file, to complex clusters of serverS providing speed, and resilience. 
### WAF (Web Application [[Firewall]])
Sits between your web request and the web server, primary purpose is to protect the webserver from hacking/denial of service attacks. It analyses web requests for common attack techniques, whether the request comes from a real user or a bot. Also checks if an excessive amount of web requests are being sent by utilising rate limiting; only allowing a certain amounts of request from an IP/second. If a request is deemed potential attack, it will be dropped, never sent to webserver.

# How Web Servers Work

## What Is a Web Server?

A web server is software that listens for incoming connections and uses a protocol (HTTP/HTTPS) to deliver web content to clients. Common examples include **Apache**, **Nginx**, and **Node.js**.

Every web server has a **root directory** — the default location it serves files from:

- Apache & Nginx → typically `/var/www/html` (Linux)
- IIS → typically `C:\inetpub\wwwroot` (Windows)

**Example:** A request for `www.example.com/picture.jpg` returns the file located at `/var/www/html/picture.jpg` on the server's hard drive.
## Virtual Hosts

A single web server can host **multiple websites** using **virtual hosts** — text-based config files that map domain names to specific directories.
**How it works:**
1. The server reads the requested hostname from the HTTP headers
2. It checks that hostname against its list of virtual hosts
3. If a match is found → serves that site's content
4. If no match → serves the default website
**Example:**

|Domain|Root Directory|
|---|---|
|`one.com`|`/var/www/website_one`|
|`two.com`|`/var/www/website_two`|
There's no limit to how many sites one server can host this way.
## Static vs. Dynamic Content
**Static vs. Dynamic Content**

- **Static Content**
    - Definition: Never changes
    - Examples: Images, CSS, JS, fixed HTML
    - How it's served: Sent directly, unmodified
- **Dynamic Content**
    - Definition: Changes based on request/context
    - Examples: Blog homepage, search results
    - How it's served: Generated/processed before sending
## Backend / Scripting Languages

Backend languages (PHP, Python, Ruby, Node.js, Perl, etc.) give websites their interactivity — connecting to databases, calling external services, and processing user input.

**Example — PHP:**

Request: `example.com/index.php?name=adam`

Server-side code:

```php
<html><body>Hello <?php echo $_GET["name"]; ?></body></html>
```

What the client actually receives:

```html
<html><body>Hello adam</body></html>
```

The client never sees the PHP code — only the resulting HTML. This backend processing is powerful, but it's also where **security vulnerabilities** commonly arise if the application isn't built securely.
