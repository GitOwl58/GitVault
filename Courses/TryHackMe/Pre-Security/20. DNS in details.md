### What is [[DNS]] ?

DNS allows us to communicate with devices on the internet without remembering complex numbers.
Like every house has an address to receive mail, every computer has its own address to communicate, the [[IP address]], looking like the following :
104.26.10.229, four sets of digits ranging from 0-255, separated by a period.
It is easier to remember the DNS (tryhackme.com), than the IP 104.26.10.229.

### Domain Hierarchy
![[Domain hierarchy.png]]
#### [[TLD]] Top level domain :
It is the end part of the domain name. (==.com== for ex)
There are two types of TLD, generic gTLD and country code ccTLD.
Historically gTLD was mean to tell the purpose of the domain (.com for commercial, .org for organisation, etc etc) and ccTLD for geographical purpose (.fr for a French domain, .uk, .ca ...)
Due to such demand, there are now more than 2000 TLDs.
#### Second level domain
Taking ==tryhackme==.com, .com is the TLD, tryhackme the Second level domain.
Limited to 63 characters + TLD, a-z 0-9 and hyphens (can't start or end with hyphens or have consecutive hyphens).

#### Subdomain
A subdomain is the left handside of the Second level domain.
Ex : ==admin==.tryhackme.com
Same creation restriction as a second level domain, but you can use multiple subdomains, ex : ==jupiter.servers==.tryhackme.com, keeping it to a max of 253 characters.

### DNS record types
DNS is not only for websites, multiple types of DNS records exist, for ex :
- A record, resolve to IPv4 addresses, **104.26.10.229**
- AAAA record, resolve to IPv6 addresses, **2606:4700:20:681a:be5**
- CNAME record, resolve to another domain name, ex TryHackMe online shop has the subdomain store.tryhackme.com returning a CNAME record shops.shopify.com. Another DNS request would then be made to shops.shopify.com to work out the IP address.
- MX record, resolve to address of the servers handling email for the domain you are querying, ex MX record response for tryhackme.com would look like alt1.aspx.l.google.com. Also comes with a priority flag. It tells the client in which order to try the servers, perfect if the main server goes down and emails needs to be sent to a backup server.
- TXT record, free text fields where any text-base data can be stored. It has multiple uses, most common can be to list servers that have the authority to send an email on behalf of the domain (helpful in the battle against spam and spoofed mail), or to verify ownership of the domain name when signing up for third party services, ex :

	- `_acme-challenge.example.com TXT "token_value_here"`
	- `@ TXT "v=spf1 ip4:192.0.2.0/24 include:_spf.google.com include:amazonses.com ~all"`
	- `_dmarc.example.com TXT "v=DMARC1; p=reject; rua=mailto:dmarc-reports@example.com; adkim=s; aspf=s; pct=100"`
	- `@ TXT "MS=ms12345678"`

### What happens when you make a DNS request ?
![[DNS request.png]]
1. When you request a domain name, your computer checks its local cache to see if you've looked up the address recently, if not, a request to your recursive DNS server will be made.
2. A recursive DNS server is usually provided by your ISP, but you can chose your own. This server also has local cache of recently looked up domain names. If a result is found locally, it's sent back to your computer, and request ends here (popular for heavily requested services, Google, Facebook, X). If it's not found locally, a journey begins to find the correct answer, starting with the internet's root DNS servers.
3. The root servers are the DNS backbone of the internet, their job is to redirect to the correct TLD server, depending of your request.   Ex : I request https://www.tryhackme.com, the root server recognises the TLD of .com and refers me to the correct TLD server that deals with .com addresses.
4. The TLD server holds records for where to find the authoritative server to answer the DNS request. The authoritative server is often known as the nameserver for the domain. Ex: tryhackme.com's name server is kip.ns.cloudflare.com and uma.ns.cloudfare.com. You often find multiple nameservers for a domain name in case backup is needed if one goes down.
5. An authoritative DNS server is the server that stores the DNS records for a particular domain name, where any updates to your domain name DNS records would be made. Depending of the record type, the DNS record is sent back to the recursive DNS server, where a local copy will be cached for future requests and then relayed back to the client who made that request. DNS records all come with a TTL value, this value is a number represented in seconds that the response should be saved for locally until you have to look it up again. Caching saves you from having to make a DNS request everytime you want to communicate with a server.
