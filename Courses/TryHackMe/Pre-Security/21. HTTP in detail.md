### What is [[HTTP]](S)?

- HTTP : Used whenever you view a website, developped by Tim Berner-Lee and his team in the 90s. It is a set of rules used to communicate with web servers for the transmitting of webpage data, whether it's HTML, images, videos, etc...
- HTTPS : The secuir version fo HTTP, encrypted so people don't see the data you are sending/receiving, and to give you assurance you're talking to the correct web server, not sommething impersonating it.
### Requests and responses

When accessing a website, browser will need to make requests to a web server for assets such as HTML, Images, and download the responses. Before that, you need to tell how and where to get these ressources, with [[URL]].
### What is a URL ? Uniform ressource locator
It is an instruction, on how to access a ressource on the internet. Here's what it looks like with all of its features.
![[Pasted image 20260812173331.png]]
- Scheme : Instructs what protocol to use [[HTTP]]/[[HTTP|HTTPS]]/[[FTP]]
- User : Some services require authentification to log in, you can put your username and password into the URL to log in.
- Host : The domain name or [[IP address]] of the server you wish to access.
- [[Ports|Port]]: The port you are going to connect to (Usually 80 for HTTP/ 443 for HTTPS, but can be hosted on any between 1-65535)
- Path : The file name or location of the ressource you want to access.
- Query string : Extra bits of info that can be sent to the requested path, ex: /blog?==id=1==, would tell the blog path that you want to receive the blog article with an id of 1.
- Fragment: A reference to a location on the actual page requested. Used for pages with long content, can even have a certain part of the page linked to it, so a viewer can see it as soon as they access the page.
### - Making a request
It is possible to make a request to a web server using on line : ==GET/HTTP.1.1==
![[Pasted image 20260812175013.png]]
For a richer experience, you need to send other data as well. The other data is sent in what we call [[HTTP Headers]], containing extra info to give to the web server you communicate with.
**Example Request:**

```http
GET / HTTP/1.1

Host: tryhackme.com
User-Agent: Mozilla/5.0 Firefox/87.0
Referer: https://tryhackme.com/
```
- Line 1: This request is sending the GET method, request the home page with / and telling the web server we use [[HTTP]] protocol version 1.1.
- Line 2: We tell the web server we want the website tryhackme.com
- Line 3: We tell the web server we are using the Firefox version 87 browser.
- Line 4: We tell the web that the web page that referred us tot his one is https://tryhackme.com
- Line 5: HTTP requests always end with a blank line to inform the web server that the request if finished.

**Example Response:**

```http
HTTP/1.1 200 OK

Server: nginx/1.15.8
Date: Fri, 09 Apr 2021 13:34:03 GMT
Content-Type: text/html
Content-Length: 98


<html>
<head>
    <title>TryHackMe</title>
</head>
<body>
    Welcome To TryHackMe.com
</body>
</html>
```
- Line 1: HTTP 1.1 is the version of the HTTP protocol the server uses, followed by the HTTP status code "200 OK", telling us our request has completed successfully.
- Line 2: This tells us the web server software, and version number.
- Line 3: The current date, time and timezone of the web server.
- Line 4: The content-type Header tells the client what sort of info is being sent, in this case text/html, could be also Images, videos, pdf, [[XML]]...
- Line 5: Content lenght tells the client how long the response is, allowing us to confirm no data is missing.
- Line 6: HTTP response contains a blank line to confirm the end of the HTTP response.
- Lines 7-14: The information has been requested, in this instance the homepage.
### HTTP Methods

HTTP methods are a way for the client to show their intended action, when making a HTTP request. A lot exist, let's cover the most common ones.
- Get request: Used to get info from a web server.
- POST request: Used to submit data to the web server, and potentially creating new words.
- PUT request: Used to submit data to a web server to update info.
- DELETE request: Used to delete info/records from a web server.
### HTTP Status codes
When a server responds, the first line always contains a status code informing of the outcome of the request, and potentially how to handle it, there are 5 range of status codes.

|                                    |                                                                                                                                                                                   |
| ---------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **100-199 - Information Response** | These are sent to tell the client the first part of their request has been accepted and they should continue sending the of their request. These codes are no longer very common. |
| **200-299 - Success**              | This range of status codes is used to tell the client their request was successful.                                                                                               |
| **300-399 - Redirection**          | These are used to redirect the client's request to another resource. This can be either to a different webpage or a different website altogether.                                 |
| **400-499 - Client Errors**        | Used to inform the client that there was an error with their request.                                                                                                             |
| **500-599 - Server Errors**        | This is reserved for errors happening on the server-side and usually indicate quite a major problem with the server handling the request.                                         |
#### Common HTTP status codes
|                                  |                                                                                                                                                                                                                               |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **200 - OK**                     | The request was completed successfully.                                                                                                                                                                                       |
| **201 - Created**                | A resource has been created (for example a new user or new blog post).                                                                                                                                                        |
| **301 - Moved Permanently**      | This redirects the client's browser to a new webpage or tells search engines that the page has moved somewhere else and to look there instead.                                                                                |
| **302 - Found**                  | Similar to the above permanent redirect, but as the name suggests, this is only a temporary change and it may change again in the near future.                                                                                |
| **400 - Bad Request**            | This tells the browser that something was either wrong or missing in their request. This could sometimes be used if the web server resource that is being requested expected a certain parameter that the client didn't send. |
| **401 - Not Authorised**         | You are not currently allowed to view this resource until you have authorised with the web application, most commonly with a username and password.                                                                           |
| **403 - Forbidden**              | You do not have permission to view this resource whether you are logged in or not.                                                                                                                                            |
| **405 - Method Not Allowed**     | The resource does not allow this method request, for example, you send a GET request to the resource /create-account when it was expecting a POST request instead.                                                            |
| **404 - Page Not Found**         | The page/resource you requested does not exist.                                                                                                                                                                               |
| **500 - Internal Service Error** | The server has encountered some kind of error with your request that it doesn't know how to handle properly.                                                                                                                  |
| **503 - Service Unavailable**    | This server cannot handle your request as it's either overloaded or down for maintenance.                                                                                                                                     |
### [[HTTP Headers]]
Headers are additional bits of data you can send to the web server when making requests.
No headers are required when making an HTTP request, although difficult to view the website properly without.
#### Common request headers
These are headers that are sent from the client (usually my browser) to the server :
- Host: Some web servers host multiple websites, so this header can tell it which one you require.
- User-agent: Your browser software and number, telling the web server this info helps it format the website properly for my browser and some elements of [[HTML]], [[Javascript]], and [[CSS]] are only available in certain browsers.
- Content-length: When sending data to a web server such as in a form, this tells the web server how much data to expect in the web request, so the server ensures it's not missing data.
- Accept-encoding: Tells the web server what type of compression methods the browser supports, so data can be made smaller for transmitting over the internet.
- [[Cookie]]: Data sent to the server to help remember my infos.
#### Common response headers
These are the headers returned to the client by the server after a request:
- Set-cookie: Info to store which gets sent back to server on each request.
- Cache control: How long to store the content of response in the browser's cache before it requests it again.
- Content-type: Tells the client what type of data is being returned(HTML/CSS/Javascript/Images/PDF/Video,etc...), using this the browser then knows how to process the data.
- Content-encoding: What method has been used to compress data to make it smaller when sending it over the internet.
### [[Cookie|Cookies]]
Small pieces of data stored on your computer, saved when a "Set-cookie" Headers is received from a web server. Every further request you make, you send the data back to the server. Because [[HTTP]] is stateless, cookies are used to remind who you are, some personal settings for the website, or whether you've been to this website before.
