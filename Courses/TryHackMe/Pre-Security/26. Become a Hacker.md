### What is offensive security ?
Focuses on testing systems by breaking into them, identifying weaknesses before attackers exploit them.
- What is exposed ?
- What can be accessed ?
- What assumption does the system make ?
### Some core terms
- Red teaming: An attack methodology, structured, authorized, simulating a real adversary to test the defenses and find vulnerabilities in a specific scope.
- Penetration test: A security assessment, structured, where an authorized tester attemps to find an and exploit vulnerabilities in a specific scope to understand the risks.
- Vulnerability: A weakness/flaw in a system, app, or config an attacker could abuse.
- Exploit: A technique used to exploit a vulnerability for a specific outcome, like accessing restricted data/functionality.
- Scope: The limits of what is allowed to be tested during an engagement, which systems/app/actions are permitted, and which are not.

### Finding weaknesses
#### [[Gobuster]]
This ethical tool runs in the terminal and automates the scanning for web pages.
Ex: `gobuster dir --url http://www.onlineshop.thm/ -w /usr/share/wordlists/dirbuster/directory-list.txt`
- `gobuster` The command-line tool used to perform the discovery of web content
- `dir` Specifies the directory and file enumeration mode, which attempts to discover hidden directories and files on a web server
- `--url http://www.onlineshop.thm/` Sets the target website that Gobuster will scan
- `-w /usr/share/wordlists/dirbuster/directory-list.txt` Specifies the [[Wordlist]] [[Gobuster]] will use to guess directory and file names
So `gobuster dir --url <InsertWebsiteURL> -w </path/to/the/wordlist.txt>`
### Exploiting weaknesses
Ethical hacking involves chaining weaknesses together. A single weakness may seem like nothing, but combined with another one could lead to serious consequences, one Domino falling after another in a chain reaction.
#### Think like a hacker
To become one, think like one, creatively, testing new ideas, in a safe and authorized way, find and prove risks before real attackers can.
Some key points:
- Asks questions: Don't assume a feature works as intented, ask yourself "What if it doesnt ?"
- Test the unexpected: Try actions/inputs developers didn't considered.
- Chain small weaknesses: A tiny flaw could be connected to create a bigger impact.
- Think like an attacker: "How would a malicious actor approach this?"
#### A valuable target
Attackers are often interested in gaining credentials (Usernames, passwords) to unlock private areas and increase their capabilities, like:
- Sensitive functionality: Features performing essential actions (Modifying data, restricted content, triggerining processes reserved to authorized users)
- User data: Private infos, names, emails, account details, to abuse/steal/sell.
- Admin features: High privilege function allowing attackers to manage users, change settings, gain full control of the app.
- Further attack opportunities: Authenticated access can allow attackers to expand their access or move deeper in the app.
#### [[Hydra]]
A password‑testing tool that automates login attempts against a target application using a [[Wordlist]].
Example of Dictionary tool technique:
`hydra -l admin -P passlist.txt www.onlineshop.thm http-post-form "/login:username=^USER^&password=^PASS^:F=incorrect" -V`
- `hydra` The command-line tool used to perform the dictionary attack
- `-l admin` Attempts to log in using the username `admin`
- `-P passlist.txt` Specifies the password list to try
- `www.onlineshop.thm` Sets the target website
- `http-post-form` Indicates that this is an POST request form
- `"/login:username=^USER^&password=^PASS^:F=incorrect"` Specifies how the login request is sent and how Hydra determines whether a login attempt has failed
- `-V` Enables verbose output, which displays each username and password attempted

So `hydra -l admin -P <Wordlistfile.txt> <TargetWebsiteURL> <http-post-form /login:username=^USER^&password=^PASS^:F=incorrect" -V``
