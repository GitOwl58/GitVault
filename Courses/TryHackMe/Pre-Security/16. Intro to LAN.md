LAN stands for Local Area Network. In [[Networking]], "topology" refers to the design or look of the network at hand.
![[Star topology.png]]
### Star Topology
Devices individually connected via a central [[Networking]] device (switch, hub). Most common today, for its reliability and scalability, despite the cost. Any information sent to a device is sent via the central device. Most expensive topology (more cabling, dedicated equipment), but much more scalable — easy to add devices as demand increases. The more it scales, the more maintenance and troubleshooting difficulty increases. Prone to failure — if the central hardware fails, all devices can't communicate.

![[Bus topology.png]]
### Bus Topology
Relies on a single connection, the backbone cable — devices stem from it like leaves on a branch. All data destined for all devices travels along the same cable, making it prone to bottlenecks and slow troubleshooting (hard to identify which device has issues when all data shares the same route). Easiest and most cost-efficient to set up. No redundancy — a single point of failure along the backbone cable means a break stops all devices from sending/receiving.

![[Ring topology.png]]

### Ring Topology
Also known as token topology. Devices connect directly to each other forming a loop — little cabling required, less dependence on hardware. Data travels the loop until it reaches its destination, using devices around the loop to forward it. A device only forwards data if it has none to send itself. Easy to troubleshoot (data travels in one direction only), but inefficient (data visits multiple devices before reaching the intended one). Less prone to bottlenecks than bus topology. Biggest disadvantage: if a cable or device is damaged, the entire network stops working.

![[A switch.png]]

### What is a [[Switch]]?
A device that aggregates (connects) multiple devices (computers, printers, any networking-capable device with ethernet) via ports (4/8/16/24/32/64). Much more efficient than hubs/repeaters — keeps track of which device is connected to which port, sending packets directly to the intended target rather than repeating to all (like a hub), reducing network traffic. Switches and routers can connect to one another to increase redundancy — if one path goes down, another can be used, at some cost to performance.

![[A router.png.png]]

### What is a [[Router]]?
A router's job is to connect networks and pass data between them, using [[Routing]] — the process of data travelling across networks by creating a path so data is successfully delivered. Useful when devices are connected by many paths.

### Subnetting
Splitting up a network into smaller, miniature networks — e.g., a business with different departments. Achieved by splitting up the number of hosts that fit in the network, represented by a **subnet mask**.

![[Subnetting.png]]

Like an [[IP address]], a subnet mask is four bytes (32 bits), each ranging 0–255. Subnets use IP addresses in three ways:
- Identify the network address
- Identify the host address
- Identify the default gateway

| Type | Purpose | Example |
|---|---|---|
| Network Address | Identifies the start of the actual network and its existence | 192.168.1.0 (for device 192.168.1.100) |
| Host Address | Identifies a device on the subnet | 192.168.1.100 |
| Default Gateway | Sends data to devices not on the same network | 192.168.1.254 |

Subnetting provides: efficiency, security, full control.

### [[ARP]]
A device can have two identifiers: a [[MAC address]] and an [[IP address]]. **Address Resolution Protocol (ARP)** allows devices to identify themselves on a network by associating a MAC address with an IP address. Each device keeps a log (CACHE) of other devices' MAC addresses.

When a device wants to communicate with another, it sends a broadcast searching for the specific device using ARP to find its MAC address:
- **ARP request**: "What is the MAC address owning this IP address?"
- **ARP reply**: Only the device owning that IP replies; the requester stores it in its ARP cache.

![[ARP request and reply.png]]

### [[DHCP]]
IP addresses can be assigned manually, or automatically via a **DHCP** (Dynamic Host Configuration Protocol) server. When a device connects without a manual IP:
1. Sends a **DHCP Discover** request
2. [[Server]] replies with a **DHCP Offer**
3. Device sends a **DHCP Request** to confirm
4. Server sends a **DHCP ACK** to finalize
