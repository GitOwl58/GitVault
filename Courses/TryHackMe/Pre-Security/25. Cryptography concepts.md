### Why cryptography matters ?
Let's picture a scenario where I need to send sensitive information to a company over the internet, travelling through dozens of computers and routers. With no protection, anyone accessing one of these could read, alter, block my data.
This is where [[Cryptography]] comes in, using mathematical rules and keys so that only authorized individuals can read it.

#### Core terms
- Plaintext: A message you can read, HELLO
- Ciphertext: A scrambled version, not supposed to make sense, KHOOR
- Key: The secret controlling how scrambling, and unscrambling works, the password to the algorithm.
- Algorithm: The recipe, the steps explaining how to use the key. Security comes from keeping this key secret.

**Encryption process = Plaintext + Encryption algorithm + Key ---> Ciphertext**
**Decryption process = Ciphertext + Decryption algorithm + Key --> Plaintext**

#### (Very bad) Example : The caesar cipher: Algorithm + Key
The caeser sipher, from Julius Caesar, shifts each letter by a fixed number of positions in the alphabet, the cipher is the algorithm, the fixed number is the key.
H E L L O = H+3 E+3 L+3 L+3 O+3 = KHOOR

#### Symmetric Encryption 
The Caesar cipher is an example of Symmetric encryption, meaning:
- The same key encrypts and decrypts the message.
- Both sender and receiver need a copy of the key.
- They key has to stay secret.
The benefits are that it is fast and efficient, so  it's good for encrypting files, drives, and network traffic, where speed matters, and can go through huge amounts of data very quickly.
The downside is, how to share that key over the internet in plain view without someone grabbing it ? It is a **Key distribution problem**, the weakness of symmetric encryption.

#### Asymmetric Encryption
Uses two mathematically linked keys:
- A public key anyonce can know/use.
- A private key kept secret by one person.
So:
- If you encrypt with someone's public key, only their private can decrypt it.
- If you encrypt with your private key, anyone with your public key can decrypt it.
It would take a computer hundreds or thousands of years to recover the private key from the public one.

Example with a mailbox:
- The mail slot at the top is the public key, anyone can drop off his letter in there, open, accessible.
- The locked door is the private key, only the owner can open and grab the letters.

The most common use of asymmetric encryption is in [[HTTP|HTTPS]].
When you visit https://google.com:
1. Your browser request the website's public key
2. This website sends back its public key wrapped in a [[Certificate]]
3. Your browser and the website use asymmetric encryption to agree on a secret without anyone else knowing.
4. From there, they switch to fast symmetric encryption using that shared key for the rest of the session.
It is sometimes called **hybrid approach**:
- Asymmetric solves the problem of key distribution
- Symmetric handles the heavy lifting because it's faster
The certificate ensures you know the public key really belongs to https://google.com:
- Contains someone's public key.
- States who that key belongs to.
- A trusted authority digitally signs it, called a Certificate authority (CA).
Browsers and OS come preloaded with a list of trusted CAs, when a website hands over a certificate:
- Your browser checks a trusted CA signed it.
- It checks that it is valid, not expired or revoked.
- If it looks good, your browser shows the padlock and trusts the public key.
#### Viewing a certificate in your Browser
- Visit any HTTPS site.
- Click the padlock icon.
- Look for Certificate/Connection is secure/View certificate.
- A window opens showing : **Issued to/Issued by/Valid from - Valid until**
## Symmetric vs Asymmetric: Side by Side

In summary, let's compare the two approaches we've covered:

|Feature|Symmetric Encryption|Asymmetric Encryption|
|---|---|---|
|Number of keys|One key for both encrypting and decrypting|Two keys: public and private|
|Key sharing|Both people need the same secret key|Public key can be shared openly|
|Speed|Very fast|Slower (used for small amounts of data)|
|Main use|Encrypting bulk data (files, network traffic)|Sharing keys, securely and digital certificates|
|Analogy|One key locks and unlocks a box|A mailbox: anyone posts, only the owner retrieves|

In practice, **real systems use both**:
- Asymmetric initiates a connection, securely sharking a symmetric key.
- Symmetric takes over until the end of session to handle data more efficiently.
