The **[[OSI Model]]** (Open Systems Interconnection) is essential in [[Networking]]. It provides a framework dictating how all networked devices send, receive and interpret data — allowing devices with different functions and designs on a network to communicate. Data sent across a network following the OSI model can be understood by other devices.

The OSI model consists of seven layers, each with a different set of responsibilities, numbered 7 to 1. Data travels through every layer; specific processes take place and information is added to the data in a process called **[[Encapsulation]]**.

![[OSI 7 layers.png]]

### Layer 1. Physical
References the physical components/hardware used in [[Networking]] — devices use electrical signals to transfer data in a [[Binary]] numbering system.

### Layer 2. Data link
Focuses on the physical addressing of the transmission. Receives a packet from the network layer (including the [[IP address]] for a remote computer) and adds the [[MAC address]] of the receiving point. Every network-enabled computer has a NIC with a unique MAC to identify it. Also presents the data in a format suitable for transmission.

### Layer 3. Network
Where [[Routing]] and re-assembly of data take place. Routing determines the most optimal path for chunks of data; re-assembly puts them back into larger chunks. Protocols include **OSPF** (Open Shortest Path First) and **RIP** (Routing Information Protocol). Route decision factors:
- Shortest path (fewest devices to travel across)
- Most reliable path (fewest lost packets historically)
- Fastest physical connection (copper vs fibre)

At this layer, everything is dealt with via IP addresses (e.g. 192.168.1.100). Routers capable of delivering packets using IP addresses are Layer 3 devices.

### Layer 4. Transport
Vital for transmitting data across the network. Data follows either:
- **[[TCP]]** (Transmission Control Protocol): reliability and guarantee — reserves a constant connection for the duration of transmission, incorporates error checking to guarantee data sent in small chunks (from layer 5) is received and reassembled in order. Used for file sharing, browsing, email.

![[TCP.png]]

- **[[UDP]]** (User Datagram Protocol): not equipped with error checking or reliability — sends data whether or not it's received, no synchronization guaranteed. Useful for small pieces of data ([[ARP]], [[DHCP]]) or larger files like video streaming, where the video is simply pixelated if data is lost.

![[UDP.png]]

### Layer 5. Session
Once data is translated and formatted (layer 6), layer 5 creates and maintains a connection to the destination computer. While the connection is active, so is the session; layer 5 closes it if inactive or lost. A session can contain "checkpoints" — if data is lost, only the newest pieces need resending, saving bandwidth. Sessions are unique; data cannot travel to another session.

### Layer 6. Presentation
Where standardisation happens — different software (e.g. email clients) can be developed differently, but data still needs to be handled the same way. Acts as a translator for data from Layer 7 so the receiving computer understands data sent in a different format. Security features like data encryption ([[HTTP]]S) occur here.

### Layer 7. Application
Where protocols and rules determine how the user interacts with data sent or received. Some applications provide a [[GUI]]; other protocols use DNS (Domain Name System) to translate website addresses into IP addresses.
