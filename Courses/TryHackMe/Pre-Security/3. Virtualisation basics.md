How companies have optimized computer components to reduce costs and build flexible, scalable systems through virtualization.

Before virtualization, if a company wanted to run a website, database, email service and an internal app, it required 4 physical servers, resulting in 5-20% usage, and a waste of resources.
- **High cost**: Buying multiple physical servers is expensive — hardware, electricity, cooling, maintenance, data center space.
- **Low utilization**: Most applications don't use the [[Server]]'s full capacity. Many servers stayed at 5–20% usage, wasting memory and storage resources.
- **Slow deployment**: Setting up new physical servers could take days or weeks.
- **Hard to scale**: If an application suddenly needed more resources, you often had to buy yet another server.

# Hypervisor

A **[[Hypervisor]]** is the core technology behind virtualization. It's the software that creates and manages VMs:
- Divides a physical computer into multiple virtual ones.
- Gives each VM its own share of CPU, memory, and storage.
- Keeps everything isolated and safe.
- Manages the lifecycle of VMs (start, stop, pause, clone, delete).

Two Hypervisor types:
- **Type 1** hypervisors run directly on the physical hardware — fast, efficient, ideal for servers and professional environments.
- **Type 2** hypervisors run within an existing operating system — easier to install, ideal for learning, testing, or small setups.

# VMs

A **[[VM]]** (Lab Machine) is a virtual computer created by the hypervisor, acting like a real machine:
- Has its own virtual CPU, RAM, storage and network.
- Can run any OS ([[Linux]], [[Windows]]...)
- Completely isolated from other VMs — if one breaks, others continue working.

You can deploy a VM using Oracle VirtualBox, VMWare Workstation... type 2 hypervisors that can run multiple OS.

Ex:
- You're running Kali Linux and want to run another OS but can't afford a whole other system — install a hypervisor and work on the OS needed (macOS, Windows...)
- You want to test whether a file is malicious without compromising your PC — set up an isolated VM to protect your main computer from getting infected.

# Containers

A **[[Container]]** is a lightweight, isolated environment that runs a single application and all the necessary components to support it. Instead of bringing a whole separate operating system, a container borrows the core of the existing system by running on the kernel — the part of an OS that communicates with hardware and manages resources such as memory and running programs.

Because containers share this kernel, they start quickly and use fewer resources than full VMs, but must match the host system's type (you can't run a Windows container on a Linux machine).

Containers behave like small, self-contained spaces because:
- They package the application and its dependencies (libraries, tools, versions).
- They share the host's operating system, so they start almost instantly.
- They remain isolated from each other, so a misbehaving container doesn't affect the others.
- They can run consistently on any machine — perfect for development, testing, and scalable deployments.

The easiest way to deploy containers is using Docker — an open-source platform that simplifies building, deploying, and running applications using containerization.

# Conclusion

- **Virtualization:** Enables a single physical computer to act like multiple separate computers.
- **[[Hypervisor]]:** The "manager" software that makes and runs VMs.
- **[[VM]]:** A whole virtual computer inside the real one, with its own system.
- **[[Container]]:** A small, isolated box for one app that shares the same system as the host.
- **Images:** A pre-packed recipe/template used to create containers.
- **Network Ports:** Special numbered entry points that apps use to talk over the network.

Key benefits of virtualization: cost savings, better resource usage, safe testing for cyber security, faster deployment, flexibility, portability, scalability, centralized management.
