### The file system

**[[File System]] Evolution on Windows:**

- **FAT16/FAT32** (File Allocation Table) — older, still used on USB drives and MicroSD cards
- **HPFS** (High Performance File System) — transitional
- **NTFS** (New Technology File System) — current standard for Windows installations

---

**Why NTFS replaced FAT:**

- Supports files larger than 4GB (FAT32 hard limit)
- Granular permissions on files and folders
- File and folder compression
- Encryption via **EFS** (Encryption File System)
- **Journaling** — in case of failure, NTFS can automatically repair files/folders using a log file. FAT cannot do this.

---

**NTFS Permissions:**

|Permission|Folders|Files|
|---|---|---|
|**Read**|View/list files and subfolders|View file contents|
|**Write**|Add files and subfolders|Write to file|
|**Read & Execute**|View, list, execute — inherited by files and folders|View, access and execute|
|**List Folder Contents**|View, list, execute — inherited by folders only|N/A|
|**Modify**|Read, write, delete folder|Read, write, delete file|
|**Full Control**|Read, write, change, delete everything|Read, write, change, delete file|

**View permissions on Windows:**  
Right-click file/folder → Properties → Security tab → select user/group

---

**Alternate Data Streams (ADS):**  
A file attribute specific to NTFS. Every file has at least one data stream (`$DATA`) but NTFS allows files to contain **multiple streams of data** — hidden from Windows Explorer by default.

- **Legitimate use:** Windows uses ADS to mark files downloaded from the internet (zone identifier)
- **Security concern:** malware writers use ADS to **hide malicious data** inside legitimate files since it's invisible to normal file browsing. Viewable via PowerShell or third-party tools.
### The windows\System32 Folders
**C:\Windows**

The traditional location of the Windows operating system. However, it doesn't have to reside on the C drive — it can technically be installed on any drive or folder. This is why Windows uses an **environment variable** to reference it rather than a hardcoded path.

The system environment variable for the Windows directory is:

```
%windir%
```

This means any program or script can reference `%windir%` without needing to know the actual drive letter — Windows resolves it automatically to wherever the OS is actually installed.

---

**[[Environment Variables]]** 

Per Microsoft: _"Environment variables store information about the operating system environment. This information includes details such as the operating system path, the number of processors used by the operating system, and the location of temporary folders."_

They act as dynamic references to system information — rather than hardcoding paths or values, programs use environment variables that Windows resolves at runtime. This makes software portable across different system configurations.

---

**System32**

Located at `C:\Windows\System32` (or `%windir%\System32`), this folder contains the critical files required for Windows to function — system libraries (`.dll` files), executables, drivers, and configuration files.

⚠️ **Extreme caution required** — accidentally deleting files or folders within System32 can render Windows completely inoperational and unbootable. Many essential Windows tools covered in security courses reside here.

### User accounts, profiles, permissions
**Account Types**

Windows has two local account types:

|Type|Capabilities|
|---|---|
|**Administrator**|Full system control — add/remove users, modify groups, change system settings, install programs|
|**Standard User**|Limited to changes within their own files/folders — cannot perform system-level actions or install programs|

---

**Viewing User Accounts**

**Method 1 — Settings:**  
Start Menu → search "Other Users" → System Settings → Other Users

Administrators see an **"Add someone else to this PC"** option — Standard Users do not.

From here you can:

- **Change account type** — promote to Administrator or demote to Standard User
- **Remove** the account

**Method 2 — Local User and Group Management:**  
Right-click Start Menu → Run → type:

```
lusrmgr.msc
```

Opens a management console with two sections:

- **Users** — all local user accounts
- **Groups** — all local groups with descriptions and members

---

**User Profiles**

When a user account logs in for the first time, Windows automatically creates a **user profile** — a personal folder containing their settings and personal files.

Profile location:

```
C:\Users\<username>
```

Every profile contains the same default folders:

- Desktop
- Documents
- Downloads
- Music
- Pictures

The **User Profile Service** handles profile creation on first login — visible as a message on the login screen during the process.

---

**Groups & Permissions**

Groups are collections of users that share the same permissions. Instead of setting permissions per user, an Administrator assigns users to groups — the user then **inherits** all permissions of that group. A user can belong to multiple groups simultaneously.

This is the foundation of **role-based access control** — a core security concept where permissions are managed at the group level rather than individually.
### User account control
**The Problem UAC Solves**

Most home users run Windows as local administrators — meaning every program they run, including malware, runs with full system privileges. If malware infects such a system, it inherits the administrator's permissions and can make any change it wants: install software, modify system files, create new accounts, etc.

Running with elevated privileges constantly is a violation of the **[[Least Privilege]]** principle — you don't need admin rights to browse the web or write a Word document.

---

**What is [[UAC User Account Control]] ?

**User Account Control** — introduced in Windows Vista, continued in all subsequent versions. A security mechanism that prevents silent privilege escalation by requiring explicit user confirmation before any operation requiring elevated permissions can execute.

**Important:** UAC does **not** apply to the built-in local Administrator account by default.

---

**How UAC Works**

Even when logged in as an Administrator, the active session does **not** run with elevated permissions by default. When an action requiring higher privileges is triggered (installing software, modifying system files, etc.), Windows:

1. **Pauses the operation**
2. **Displays a UAC prompt** asking the user to confirm
3. **Proceeds only if confirmed** — if no response is given, the prompt disappears and the action is cancelled

This means [[Malware]] cannot silently elevate its own privileges — it needs explicit human approval first.

---

**UAC for Standard Users**

When a Standard User attempts an action requiring elevation:

- A **shield icon** appears on programs that will trigger a UAC prompt
- The UAC prompt asks for an **Administrator account password** — not just a confirmation
- If the password is not entered within a timeout period, the prompt disappears and the action is blocked

This is a critical distinction — Standard Users must provide admin credentials, Administrators just need to click confirm.

---

**Security Impact**

UAC significantly reduces the risk of malware compromise by:

- Breaking the assumption that all code runs with admin rights
- Requiring human interaction for privilege escalation
- Making silent background infections much harder to execute

It is not perfect — **UAC bypass techniques** exist and are used by sophisticated malware — but it remains an important layer of defense in depth.
### Settings and control panel
**Two Ways to Configure Windows**

Windows provides two interfaces for system configuration that coexist and sometimes overlap:

**Control Panel** — the traditional, long-standing configuration interface. More complex settings, more granular control. Been part of Windows for decades.

**Settings** — introduced in Windows 8 (designed for touchscreen/tablet use), continued and expanded in Windows 10/11. Simpler, more modern interface. Now the primary go-to for most users.

---

**Key Differences**

- Settings handles most common, everyday changes (wallpaper, display, accounts, updates)
- Control Panel handles more complex/advanced configurations
- They're not fully separate — some Settings options redirect to Control Panel for advanced options (e.g. Network & Internet → Change adapter options opens a Control Panel window)
- When unsure which to use, just **search from the Start Menu** — Windows will find the right location regardless of which interface hosts it

---

**Viewing Installed Applications**

To see all software installed on the system:

Control Panel → **Programs** → **Programs and Features**

Lists all installed applications with:

- Name
- Publisher
- Version
- Install date

Useful for auditing a system — verifying what software has been added, spotting unauthorized or suspicious installations.

---

**Tip: When in doubt, search**

Rather than remembering which interface holds which setting, just use the Start Menu search. Searching "wallpaper", "printer", "firewall" etc. returns direct links to the relevant settings page, whether it lives in Settings or Control Panel.
### Task manager
Task Manager is a built-in Windows utility providing a real-time overview of everything running on the system.

**Access methods:**

- Right-click taskbar → Task Manager
- Keyboard shortcut: **Ctrl + Shift + Esc**
- Ctrl + Alt + Delete → Task Manager

---

**What it shows:**

**Simple View** — just lists open applications, minimal information.

**Detailed View** (click "More details") — full breakdown across multiple tabs:

- **Processes** — all running applications and background processes, with CPU/RAM/Disk/Network usage per process
- **Performance** — real-time graphs for CPU, Memory, Disk, and Network utilization
- **App history** — resource usage over time per application
- **Startup** — programs that launch on boot (and their impact on startup time)
- **Users** — active user sessions and their resource consumption
- **Details** — granular process list with PIDs, status, and resource usage
- **Services** — running Windows services

---

**Security relevance:**  
Task Manager is a first-response tool for investigating a system — checking for suspicious processes consuming unexpected resources, identifying unknown programs, or spotting malware running in the background. The **Details** tab showing PIDs connects directly to the `[[PID]]` concept.
