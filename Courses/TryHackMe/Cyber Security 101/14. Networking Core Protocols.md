### [[DNS]] Records
DNS maps domain names to IPs at OSI Layer 7, over port 53 (UDP, falling back to TCP). Four common record types (full list in [[DNS Record]]):
- **A** — hostname → one or more IPv4 addresses
- **AAAA** — same as A but IPv6 (quad-A, not to be confused with battery size or Authentication/Authorization/Accounting)
- **CNAME** — domain name → another domain name
- **MX** — the mail server responsible for a domain's email

A browser resolving `example.com` queries for the A record; an email to `test@example.com` triggers an MX lookup. `nslookup <domain>` looks these up from the CLI.

---
### [[WHOIS]]
Registering a domain grants the authority to set its DNS records — and requires accurate registrant contact info, which becomes publicly queryable as a **WHOIS record** (name, phone, email, address, creation/update dates). Privacy services can hide this info from public WHOIS lookups. Query via the `whois <domain>` CLI tool or an online WHOIS service.

### [[HTTP]](S): Accessing the Web
Browser communication protocol — GET/POST/PUT/DELETE (see [[HTTP methods]]) over TCP port 80 (HTTP) or 443 (HTTPS), occasionally 8080/8443. `telnet <ip> 80` + `GET / HTTP/1.1` + `Host: anything` lets you "talk HTTP" manually for troubleshooting — swap the path after `GET` to request a different file.

---
### [[FTP]]: Transferring Files
Purpose-built for file transfer — more efficient than HTTP for that job. TCP port 21 by default; the actual file/data transfer happens over a separate connection. Client commands: `USER`/`PASS` to authenticate, `RETR` to download, `STOR` to upload. Many FTP servers allow anonymous login (username `anonymous`, no password) with a limited file set.

---
### [[SMTP]]: Sending Email
Governs how a mail client hands an email to a mail server, and how mail servers relay to each other — like handing a package to the post office. TCP port 25 by default. Commands: `HELO`/`EHLO` opens the session, `MAIL FROM`/`RCPT TO` set sender/recipient, `DATA` starts the message body, a lone `.` ends it.

---
### [[POP3]]: Receiving Email
Client downloads mail from the server, typically deleting it server-side afterward — like clearing out a physical mailbox. TCP port 110 by default. Commands: `USER`/`PASS` to authenticate, `STAT`/`LIST` to check message count/size, `RETR <n>` to download, `DELE <n>` to mark for deletion, `QUIT` to apply changes.

---
### [[IMAP]]: Synchronizing Email
Keeps mail on the server and synchronizes state (read/moved/deleted) across multiple clients — unlike POP3, which minimizes server storage by deleting after download. Better fit for checking the same mailbox from several devices. TCP port 143 by default. Commands: `LOGIN`, `SELECT <mailbox>`, `FETCH <n> <data item>`, `MOVE`/`COPY`, `LOGOUT`.

⚠️ None of DNS/WHOIS/HTTP/FTP/SMTP/POP3/IMAP are encrypted by default — anyone capturing the traffic (e.g. via Wireshark) can read commands and credentials in plaintext. Their secure counterparts are covered separately.
