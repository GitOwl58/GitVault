### [[Tcpdump]]
Command-line packet capture and analysis tool, pre-installed on most Linux distributions. Unlike [[Wireshark]]'s GUI, everything happens through flags: capture live traffic, read/write `.pcap` files, and filter down to exactly the packets worth inspecting, all from the terminal, which makes it the natural choice on a remote box with no desktop environment.

---
### Basic Packet Capture
Running `tcpdump` with no arguments works, but only confirms it's installed: any real use needs to be specific about the interface, the count, and how the output is displayed.

- `-i INTERFACE`: listen on a specific interface, e.g. `-i eth0`; `-i any` listens on all of them. `ip a s` lists the available interfaces (e.g. `lo` for loopback, `ens5` for the main NIC).
- `-w FILE`: write captured packets to a file instead of printing them (usually `.pcap`); nothing scrolls on screen while this runs, and the file can be reopened later, including in Wireshark.
- `-r FILE`: read packets back from a saved file; useful for studying protocol behaviour after the fact, or analysing a capture that caught an actual attack. Doesn't require root.
- `-c COUNT`: stop after capturing COUNT packets; without it, capture runs until interrupted (**[CTRL]+[C]**).
- `-n` / `-nn`: skip DNS resolution of IP addresses (`-n`), or skip both DNS *and* port-to-service-name resolution (`-nn`, e.g. `80` stays `80` instead of becoming `http`).
- `-v` / `-vv` / `-vvv`: increasing verbosity. `-v` alone adds TTL, identification, total length, and IP options to the output; each extra `v` adds more.

Capturing live traffic requires root (`sudo`); reading from an existing file doesn't.

Example capture, 5 packets, no address resolution:
```
sudo tcpdump -i ens5 -c 5 -n
listening on ens5, link-type EN10MB (Ethernet), capture size 262144 bytes
08:55:18.989213 IP 10.10.117.2.22 > 10.11.81.126.53378: Flags [P.], seq 2888580014:2888580210, ack 771262362, win 922, length 196
...
5 packets captured
```

**Cheatsheet:**

| Command | Explanation |
|---|---|
| `tcpdump -i INTERFACE` | Capture on a specific interface |
| `tcpdump -w FILE` | Write captured packets to a file |
| `tcpdump -r FILE` | Read captured packets from a file |
| `tcpdump -c COUNT` | Stop after COUNT packets |
| `tcpdump -n` | Don't resolve IP addresses |
| `tcpdump -nn` | Don't resolve IP addresses or port numbers |
| `tcpdump -v` | Verbose (stack with `-vv`/`-vvv` for more) |

Example combos: `tcpdump -i eth0 -c 50 -v` (50 packets on Ethernet, verbose); `tcpdump -i wlo1 -w data.pcap` (capture on Wi-Fi, write to file, runs until interrupted); `tcpdump -i any -nn` (all interfaces, no resolution at all).

### Filtering Expressions
![[Tcpdump filtering expressions illustration.png|300]]
Running tcpdump with no filter at all is rarely useful: a busy interface sees far more traffic than anyone can read through packet by packet, so the goal is always to narrow down to exactly what's worth inspecting.

**By host:** `host IP` or `host HOSTNAME` limits capture to packets exchanged with that host, e.g. `sudo tcpdump host example.com -w http.pcap`. `src host`/`dst host` narrow it further to just one direction.

**By port:** `port PORT_NUMBER` limits capture to that port in either direction, e.g. `sudo tcpdump -i ens5 port 53 -n` to watch DNS traffic (both UDP and TCP use port 53). `src port`/`dst port` narrow it to source or destination only.

**By protocol:** the protocol name alone limits capture to it, e.g. `ip`, `ip6`, `tcp`, `udp`, `icmp`. `sudo tcpdump -i ens5 icmp -n` shows ICMP traffic only: an echo request/reply pair (someone running `ping`), or an ICMP Time Exceeded (someone running `traceroute`, see [[ICMP]]).

**Cheatsheet:**

| Command | Explanation |
|---|---|
| `tcpdump host IP`/`HOSTNAME` | Filter by IP or hostname |
| `tcpdump src host IP` | Filter by source host only |
| `tcpdump dst host IP` | Filter by destination host only |
| `tcpdump port PORT_NUMBER` | Filter by port, either direction |
| `tcpdump src port PORT_NUMBER` | Filter by source port only |
| `tcpdump dst port PORT_NUMBER` | Filter by destination port only |
| `tcpdump PROTOCOL` | Filter by protocol (`ip`, `ip6`, `icmp`...) |

### Logical Operators
Three operators combine filters: **and** (both conditions true, e.g. `host 1.1.1.1 and tcp`), **or** (either condition true, e.g. `udp or icmp`), **not** (condition false, e.g. `not tcp` shows everything except TCP, i.e. UDP/ICMP/ARP).

Reading packets back from a saved file works the same way: `tcpdump -r traffic.pcap -c 5 -n` shows the first 5 packets without resolving addresses; piping through `wc` counts matches, e.g. `tcpdump -r traffic.pcap src host 192.168.124.1 -n | wc` to count how many packets came from one host.

**Combined examples:** `tcpdump -i any tcp port 22` (SSH traffic, any interface); `tcpdump -i wlo1 udp port 123` (NTP traffic on Wi-Fi); `tcpdump -i eth0 host example.com and tcp port 443 -w https.pcap` (HTTPS traffic to that host, saved to a file).

### Advanced Filtering: Header Bytes, Binary Operations and TCP Flags
![[Tcpdump advanced filtering illustration.png|300]]
Beyond host/port/protocol, tcpdump can also filter on the raw contents of a protocol header byte, using `proto[expr:size]`: `proto` is the protocol (`arp`, `ether`, `icmp`, `ip`, `ip6`, `tcp`, `udp`), `expr` is the byte offset (0 = first byte), `size` is how many bytes to read (1, 2, or 4; defaults to 1).

This relies on **[[Bitwise Operations]]**, three operations on individual bits: **AND** (`&`, returns 1 only if both bits are 1), **OR** (`|`, returns 1 if either bit is 1), **NOT** (`!`, flips a single bit). Two worked examples from the `pcap-filter` manual page:
- `ether[0] & 1 != 0`: takes the first byte of the Ethernet header, ANDs it with `1` (binary `00000001`), and matches if the result isn't 0, catching packets sent to a multicast Ethernet address.
- `ip[0] & 0xf != 5`: takes the first byte of the IP header, ANDs it with hex `f` (binary `00001111`), and matches if the result isn't 5 (binary `00000101`), catching IP packets that carry options.

The more practical version of this is filtering on **[[TCP Flags]]** directly via `tcp[tcpflags]`, comparing against `tcp-syn`, `tcp-ack`, `tcp-fin`, `tcp-rst`, `tcp-push`:
- `tcpdump "tcp[tcpflags] == tcp-syn"`: only the SYN flag set, nothing else.
- `tcpdump "tcp[tcpflags] & tcp-syn != 0"`: at least SYN set (others may also be set).
- `tcpdump "tcp[tcpflags] & (tcp-syn|tcp-ack) != 0"`: at least SYN or ACK set.

`greater LENGTH` and `less LENGTH` filter by packet size. Full syntax reference: `man pcap-filter`.

### Displaying Packets
Five options change how captured packets are printed:
- `-q`: quick output, one brief line per packet (timestamp, source/destination IP:port, protocol, length).
- `-e`: include the link-level header, i.e. source/destination [[MAC address]]es; useful for studying ARP/DHCP or tracking down unusual traffic by its hardware address.
- `-A`: show packet contents as ASCII; readable when the payload is plaintext, useless once it's encrypted or compressed.
- `-xx`: show packet contents in hexadecimal, works regardless of encoding, since every octet is just two hex digits.
- `-X`: hex and ASCII side by side, the "best of both worlds" view.

**Cheatsheet:**

| Command | Explanation |
|---|---|
| `tcpdump -q` | Quick, brief per-packet summary |
| `tcpdump -e` | Include MAC addresses |
| `tcpdump -A` | Show packet data as ASCII |
| `tcpdump -xx` | Show packet data in hex |
| `tcpdump -X` | Hex and ASCII together |
