### [[Wireshark]]
Open-source, cross-platform packet analyser: captures live traffic and inspects existing capture files (`.pcap`/`.pcapng`). Not an IDS: it only reads and displays packets, never modifies or blocks them, so spotting anomalies is on the analyst. Used to troubleshoot network problems, spot security anomalies (rogue hosts, odd ports, suspicious traffic), and study protocols in depth.

---
### Interface
![[Wireshark main window.png]]
Five main areas before loading a capture: **Toolbar** (filtering/sorting/exporting/merging shortcuts), **Display Filter Bar**, **Recent Files**, **Capture Filter and Interfaces** (available sniffing NICs, e.g. `eth0`), **Status Bar** (profile, packet counts). Once a capture is loaded, three panes break down each packet: **Packet List** (one-line summary per packet), **Packet Details** (protocol breakdown of the selected packet), **Packet Bytes** (hex/ASCII, highlights alongside whatever's selected in Packet Details).
![[Packet panes overview.png]]

---
### Packet Colouring
Packets are colour-coded by protocol/condition to spot patterns at a glance. **Temporary** rules only last the session; **permanent** rules save to the profile (View → Coloring Rules). "Colourise Packet List" toggles colouring on/off entirely.
![[Default colouring rules.png|500]]

---
### Capturing and Merging
The shark-fin button starts a capture, red stops it, green restarts it; the status bar shows the interface and live packet count. File → Merge combines two pcap files into one (save the result before working on it). File → Capture File Properties (or the pcap icon, bottom-left) shows file hash, capture time, comments, interface, and stats.

---
### Packet Dissection ([[OSI Model]])
Clicking a packet opens its details across up to 7 layers, each highlighting the matching bytes in the Packet Bytes pane:
- **Frame**: physical-layer capture metadata
- **Source [MAC]**: Data Link layer, source/destination [[MAC address]]es
- **Source [IP]**: Network layer, source/destination [[IP address]]es
- **Protocol**: Transport layer, [[TCP]]/[[UDP]] and source/destination [[Ports|ports]]
- **Protocol Errors**: reassembled TCP segments
- **Application Protocol**: Application layer, e.g. [[HTTP]]
- **Application Data**: the actual application payload

---
### Navigation
- **Packet Numbers**: unique per-packet ID, used to jump around a capture
- **Go to Packet**: jump straight to a number, or the next packet in a conversation
- **Find Packet** (Edit → Find Packet): search by Display filter, Hex, String, or Regex, across the packet list/details/bytes pane; case-insensitive by default
- **Mark Packets**: flags a packet in black for later reference, lost once the file closes
- **Packet Comments**: persist inside the capture file (unlike marks)
- **Export Packets**: save a chosen subset to a new file
- **Export Objects**: pull transferred files straight out of a stream (DICOM, HTTP, IMF, TFTP only)
- **Time Display Format**: default is seconds-since-capture-start, switchable to a readable format (View → Time Display Format)

### Expert Info
Flags protocol anomalies by severity: **Chat** (blue, routine), **Note** (cyan, notable events like app error codes), **Warn** (yellow, unusual errors), **Error** (red, malformed packets). Common groups: Checksum, Comment, Deprecated, Malformed. Viewed via Analyse → Expert Information.
![[Expert Information dialog.png]]

---
### Filtering
Two filter types: **capture filters** (only capture matching traffic) and **display filters** (hide/show within an already-captured file); display filters covered in depth in the next room. Right-click shortcuts on any field:
- **Apply as Filter**: filters on that single value immediately
- **Conversation Filter**: filters to every packet in that IP/port conversation
- **Colourise Conversation**: highlights the conversation without touching the active filter or packet count
- **Prepare as Filter**: builds the query without applying it, so it can be combined with and/or
- **Apply as Column**: adds that field as its own column in the Packet List pane
- **Follow Stream**: reconstructs the full application-level conversation (server packets blue, client red); can reveal cleartext credentials

![[Display filter bar.png|500]]
Basic display filter syntax: protocol name alone (`http`, `arp`, `dhcp`, `ftp`...), `tcp.port == 80` / `udp.port == <port>` for a port, `ip.addr == 192.168.1.2` for an address.
