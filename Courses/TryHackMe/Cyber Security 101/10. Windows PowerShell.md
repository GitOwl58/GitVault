## [[PowerShell]] Basics: Launching and Core Cmdlets

### Launching PowerShell

From a Windows GUI, PowerShell can be launched in several ways:

- **Start Menu**: type `powershell` in the search bar, then select PowerShell from the results.
- **Run Dialog**: press `Win + R`, type `powershell`, and hit Enter.
- **File Explorer**: navigate to any folder, type `powershell` in the address bar, and press Enter — this opens PowerShell in that directory.
- **Task Manager**: open Task Manager, go to File > Run new task, type `powershell`, and press Enter.

It can also be launched from an existing Command Prompt (`cmd.exe`) by typing `powershell` and pressing Enter:

```
C:\Users\captain>powershell
Windows PowerShell
Copyright (C) Microsoft Corporation. All rights reserved.

PS C:\Users\captain>
```

Once launched, the prompt changes to `PS` (PowerShell) followed by the current working directory.

### Basic Syntax: Verb-Noun

PowerShell commands are called **cmdlets** (pronounced "command-lets"). They follow a consistent **Verb-Noun** naming convention: the verb describes the action, and the noun specifies the object the action applies to.

Examples:

- `Get-Content`: retrieves the content of a file and displays it in the console.
- `Set-Location`: changes the current working directory.

Similar to the `dir` command in Command Prompt (or `ls` in Unix-like systems), `Get-ChildItem` lists the files and directories in a location specified with the `-Path` parameter. If no path is specified, the cmdlet displays the contents of the current working directory.

### Changing Directory: Set-Location

To navigate to a different directory, use `Set-Location`. It changes the current directory to the specified path, similar to `cd` in Command Prompt:

```
PS C:\Users\captain> Set-Location -Path ".\Documents"
PS C:\Users\captain\Documents>
```

### Creating Items: New-Item

While the traditional Windows command line uses separate commands to create different items like directories and files, PowerShell simplifies this by using a single cmdlet, `New-Item`, to handle both. You need to specify the path of the item and its type (`Directory` or `File`).

```
PS C:\Users\captain\Documents> New-Item -Path ".\captain-cabin\captain-wardrobe" -ItemType "Directory"

    Directory: C:\Users\captain\Documents\captain-cabin

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d-----          9/4/2024  12:20 PM                captain-wardrobe

PS C:\Users\captain\Documents> New-Item -Path ".\captain-cabin\captain-wardrobe\captain-boots.txt" -ItemType "File"

    Directory: C:\Users\captain\Documents\captain-cabin\captain-wardrobe

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----          9/4/2024  11:46 AM              0 captain-boots.txt
```

### Removing Items: Remove-Item

Similarly, `Remove-Item` removes both directories and files, whereas the traditional Windows command line uses separate commands (`rmdir` and `del`):

```
PS C:\Users\captain\Documents> Remove-Item -Path ".\captain-cabin\captain-wardrobe\captain-boots.txt"
PS C:\Users\captain\Documents> Remove-Item -Path ".\captain-cabin\captain-wardrobe"
```

## PowerShell Piping and Filtering

### What Is Piping

Piping is a technique used in command-line environments that allows the output of one command to be used as input for another, creating a sequence of operations where data flows from one command to the next. Represented by the `|` symbol, piping is widely used in the Windows CLI as well as in Unix-based shells.

In PowerShell, piping is more powerful because it passes **objects** rather than just text. These objects carry not only data but also the properties and methods that describe and interact with that data.

For example, to get a list of files in a directory and sort them by size:

```
PS C:\Users\captain\Documents\captain-cabin> Get-ChildItem | Sort-Object Length

    Directory: C:\Users\captain\Documents\captain-cabin

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----          9/4/2024  12:50 PM              0 captain-boots.txt
-a----          9/4/2024  12:14 PM            264 captain-hat2.txt
-a----          9/4/2024  12:14 PM            264 captain-hat.txt
-a----          9/4/2024  12:37 PM           2116 ship-flag.txt
d-----          9/4/2024  12:50 PM                captain-wardrobe
```

Here, `Get-ChildItem` retrieves the files as objects, and the pipe sends them to `Sort-Object`, which sorts them by their `Length` (size) property. This object-based approach allows for detailed, flexible command sequences.

### Filtering with Where-Object

`Where-Object` filters objects based on specified conditions, returning only those that meet the criteria. For example, to list only `.txt` files in a directory:

```
PS C:\Users\captain\Documents\captain-cabin> Get-ChildItem | Where-Object -Property "Extension" -eq ".txt"

    Directory: C:\Users\captain\Documents\captain-cabin

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----          9/4/2024  12:50 PM              0 captain-boots.txt
-a----          9/4/2024  12:14 PM            264 captain-hat.txt
-a----          9/4/2024  12:14 PM            264 captain-hat2.txt
-a----          9/4/2024  12:37 PM           2116 ship-flag.txt
```

Here, `Where-Object` filters files by their `Extension` property, keeping only files equal (`-eq`) to `.txt`.

#### Comparison Operators

`-eq` ("equal to") is one of a set of comparison operators shared with other scripting languages (e.g., Bash, Python):

- `-ne`: "not equal" — excludes objects matching the specified criteria.
- `-gt`: "greater than" — a strict comparison; objects equal to the specified value are excluded.
- `-ge`: "greater than or equal to" — the non-strict version of `-gt` (a combination of `-gt` and `-eq`).
- `-lt`: "less than" — a strict comparison; only objects strictly below the value are included.
- `-le`: "less than or equal to" — the non-strict version of `-lt` (a combination of `-lt` and `-eq`).

Objects can also be filtered by matching a property against a pattern using `-like`:

```
PS C:\Users\captain\Documents\captain-cabin> Get-ChildItem | Where-Object -Property "Name" -like "ship*"

    Directory: C:\Users\captain\Documents\captain-cabin

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
-a----          9/4/2024  12:37 PM           2116 ship-flag.txt
```

### Selecting Properties with Select-Object

`Select-Object` selects specific properties from objects or limits the number of objects returned. It's useful for refining output to show only the details needed:

```
PS C:\Users\captain\Documents\captain-cabin> Get-ChildItem | Select-Object Name,Length

Name              Length
----              ------
captain-wardrobe
captain-boots.txt 0
captain-hat.txt   264
captain-hat2.txt  264
ship-flag.txt     2116
```

### Building Longer Pipelines

Pipelines aren't limited to two cmdlets — more commands can be chained together. For example, combining `Sort-Object` and `Select-Object` can display the largest file in a directory:

```
PS C:\Users\captain\Documents\captain-cabin> Get-ChildItem | Sort-Object Length -Descending | Select-Object -First 1
```

### Searching Text with Select-String

`Select-String` searches for text patterns within files, similar to `grep` in Unix-based systems or `findstr` in Windows Command Prompt. It's commonly used to find specific content within log files or documents:

```
PS C:\Users\captain\Documents\captain-cabin> Select-String -Path ".\captain-hat.txt" -Pattern "hat"

captain-hat.txt:8:Don't touch my hat!
```

`Select-String` fully supports regular expressions, allowing complex pattern matching for searching and analyzing text data.

### PowerShell Scripting and Remote Execution

### What Is Scripting

Scripting is the process of writing and executing a series of commands contained in a text file, known as a script, to automate tasks that would otherwise be performed manually in a shell.

Scripting is essentially giving a computer a to-do list, where each line in the script is a task the computer carries out automatically. This saves time, reduces the chance of errors, and allows tasks that are too complex or tedious to perform manually. Scripts are powerful tools for managing systems, processing data, and more.

Learning scripting with PowerShell goes beyond the scope of this lesson, but its power makes it a crucial skill across cyber security roles:

- **Incident responders, malware analysts, and threat hunters** can use PowerShell scripts to automate log analysis, detect anomalies, and extract indicators of compromise (IOCs). Scripts can also help reverse-engineer malicious code or automate scanning systems for signs of intrusion.
- **Red team members, including penetration testers and ethical hackers**, can use PowerShell scripts to automate system enumeration, execute remote commands, and craft obfuscated scripts to bypass defenses. Its deep integration with all types of systems makes it powerful for simulating attacks and testing resilience against real-world threats.
- **System administrators** benefit from PowerShell scripting for automating checks, managing system configurations, and securing networks, especially in remote or large-scale environments. Scripts can enforce security policies, monitor system health, and respond automatically to security incidents.

Whether used defensively or offensively, PowerShell scripting is an essential capability in the cyber security toolkit.

### Remote Execution: Invoke-Command

`Invoke-Command` is essential for executing commands on remote systems, making it fundamental for system administrators, security engineers, and penetration testers. It enables efficient remote management and, combined with scripting, automation of tasks across multiple machines. It can also be used to execute payloads or commands on target systems during an engagement by penetration testers — or attackers.

Example usage can be found via `Get-Help Invoke-Command -examples`:

```
PS C:\Users\captain> Get-Help Invoke-Command -examples

NAME
    Invoke-Command

SYNOPSIS
    Runs commands on local and remote computers.

    ------------- Example 1: Run a script on a server -------------

    Invoke-Command -FilePath c:\scripts\test.ps1 -ComputerName Server01

    The FilePath parameter specifies a script that is located on the local computer. The script runs
    on the remote computer and the results are returned to the local computer.

    --------- Example 2: Run a command on a remote server ---------

    Invoke-Command -ComputerName Server01 -Credential Domain01\User01 -ScriptBlock { Get-Culture }

    The ComputerName parameter specifies the name of the remote computer. The Credential parameter
    is used to run the command in the security context of Domain01\User01, a user who has permission
    to run commands. The ScriptBlock parameter specifies the command to be run on the remote computer.

    In response, PowerShell requests the password and an authentication method for the User01 account.
    It then runs the command on the Server01 computer and returns the result.
[...]
```

These two examples illustrate the simplicity and power of `Invoke-Command`:

- **Example 1** shows how the cmdlet can be combined with any custom script to automate tasks on remote computers using `-FilePath`.
- **Example 2** shows that scripting knowledge isn't required to benefit from `Invoke-Command`. By appending `-ScriptBlock { ... }`, any command (or sequence of commands) can be executed on the remote computer — with the same result as typing those commands directly in a local PowerShell session on that machine.
