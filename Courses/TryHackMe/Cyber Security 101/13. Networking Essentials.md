### [[DHCP]]: Automatic Network Configuration
Joining a network needs at least an [[IP address]]/subnet mask, a [[Router|gateway]], and a DNS server. Manual config is fine for servers (they don't roam), but automating it avoids both the manual effort and IP address conflicts (two devices claiming the same address). **DHCP** is the application-layer protocol that does this (server listens on UDP port 67, client sends from UDP port 68).

Four-step handshake, **DORA**:
1. **Discover**: client broadcasts `DHCPDISCOVER` looking for a server
2. **Offer**: server responds `DHCPOFFER` with an available IP
3. **Request**: client responds `DHCPREQUEST` accepting the offered IP
4. **Acknowledge**: server responds `DHCPACK`, confirming the assignment

Until the handshake completes, the client has no IP config yet, so Discover/Request packets are sent from `0.0.0.0` to the broadcast address `255.255.255.255`, at the link layer to the broadcast MAC `ff:ff:ff:ff:ff:ff`. At the end, the client has its leased IP, gateway, and DNS server.

### [[ARP]]: Layer 3 to Layer 2
Two hosts on the same Ethernet/WiFi need each other's MAC address to actually frame their IP packets; knowing the destination IP isn't enough. Devices don't need each other's MAC addresses at rest; only while communicating (a DHCP-configured device already knows its gateway/DNS *IPs*, no MACs needed until it talks link-local).

**ARP** resolves an IP to a MAC on the local Ethernet:
- **ARP Request**: broadcast (`ff:ff:ff:ff:ff:ff`) asking "who has this IP?"
- **ARP Reply**: the owning host responds with its MAC address

Debated whether ARP is Layer 2 (deals in MAC addresses) or Layer 3 (supports IP operations); what matters is it bridges the two.

### [[ICMP]]: Network Diagnostics
**ICMP** is used for diagnostics and error reporting, mainly via two commands:

- **ping**: sends an **ICMP Echo Request** (Type 8), target replies with an **Echo Reply** (Type 0); measures round-trip time (RTT). No reply can mean the target is down, or a firewall is blocking it.
- **traceroute** (`tracert` on Windows): discovers every router hop between you and a target, using [[TTL]]

**How traceroute works:** every packet's [[TTL]] field caps how many routers it can cross; each router decrements it by one, and a router that decrements TTL to zero drops the packet and replies with an **ICMP Time Exceeded** (Type 11). traceroute sends packets with increasing TTL (1, 2, 3…) to force each router along the path to reveal itself in turn. Some routers don't respond at all (dropped silently); ISP routers may reveal a private IP; public-IP hops can be reverse-looked-up for domain/geolocation. The route can change between runs.

---
### Routing Protocols
Once a packet needs to cross multiple networks, routers need an algorithm to pick the best link. [[Routing protocols]] let routers share topology/reachability info to build that path; the main ones are [[OSPF]], [[EIGRP]], [[BGP]], [[RIP]].

---
### [[NAT]]
IPv4 only has ~4 billion addresses, nowhere near enough for every connected device. **NAT** lets many devices on a private range share one public IP: the router rewrites the source IP *and port* of outgoing packets to its own public IP and a chosen port, keeping a translation table to map replies back to the right internal device/port. E.g. a laptop at `192.168.0.129:15401` is seen externally as `212.3.4.5:19273`, translated seamlessly by the router.
