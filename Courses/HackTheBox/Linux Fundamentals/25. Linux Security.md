Every system carries intrusion risk, more so an internet-facing host with complex web apps; Linux is generally less virus-prone than Windows and has a smaller attack surface than an Active-Directory-joined host, but still needs baseline hardening.

Core measures:
- **Keep the OS and packages current**: `apt update && apt dist-upgrade`.
- **Restrict traffic** at the network level or via `iptables` if network-level rules aren't in place.
- **Harden SSH**: disallow password login (key-based only) and disallow root login over SSH.
- **Least privilege**: avoid administering as root directly; grant specific commands via `sudoers` instead of blanket sudo rights.
- **[[Fail2ban]]**: counts failed logins and blocks/handles offending hosts once a threshold is hit.
- **Periodic auditing**: watch for an out-of-date kernel (manual updates are often forgotten), user permission issues, world-writable files, and misconfigured cron jobs or services, all classic privilege-escalation vectors.
- **[[SELinux]]** / **[[AppArmor]]**: kernel-level MAC modules labelling every process/file/object and enforcing policy rules between them, down to fine-grained actions like append-only or move permissions.
- Security-focused utilities worth knowing: [Snort](https://www.snort.org/) (IDS), [chkrootkit](http://www.chkrootkit.org/), [rkhunter](https://packages.debian.org/sid/rkhunter), [Lynis](https://cisofy.com/lynis/).
- Baseline hygiene: disable unnecessary services/software, remove unencrypted-auth services, keep NTP and Syslog running, one account per user, enforce strong passwords, password aging, lock accounts after repeated failures, disable unneeded SUID/SGID binaries.

Security is a process, not a fixed checklist: how well a system is protected tracks how well its administrators understand and maintain it.

### TCP Wrappers
**[[TCP Wrappers]]** restrict which hosts can reach which services, checked against `/etc/hosts.allow` and `/etc/hosts.deny` before a connection is granted:
```
# hosts.allow
sshd : 10.129.14.0/24
ftpd : 10.129.14.10
telnetd : .inlanefreight.local

# hosts.deny
ALL : .inlanefreight.com
sshd : 10.129.22.22
ftpd : 10.129.22.0/24
```
Rule order matters: the first match wins. TCP Wrappers control *service* access, not ports, so they complement rather than replace a real firewall.
