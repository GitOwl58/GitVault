Task scheduling lets tasks run automatically at a specific time or interval, without manual triggering: updates, scripts, cleanup, backups. Two main mechanisms on Linux.

### Systemd Timers
**[[systemd]]** can schedule via a timer + service pair:
1. Create a timer unit, e.g. `/etc/systemd/system/mytimer.timer`:
```
[Unit]
Description=My Timer
[Timer]
OnBootSec=3min
OnUnitActiveSec=1hour
[Install]
WantedBy=timers.target
```
`OnBootSec` runs it once after boot; `OnUnitActiveSec` runs it repeatedly at that interval.

2. Create the matching service, e.g. `mytimer.service`:
```
[Unit]
Description=My Service
[Service]
ExecStart=/full/path/to/my/script.sh
[Install]
WantedBy=multi-user.target
```
3. `sudo systemctl daemon-reload`, then `sudo systemctl start mytimer.service` and `sudo systemctl enable mytimer.service` to autostart it.

### Cron
**[[Cron]]** schedules jobs via a `crontab` file read by the cron daemon, structured as five time fields (minute 0-59, hour 0-23, day-of-month 1-31, month 1-12, day-of-week 0-7) followed by the command to run:
```
0 */6 * * * /path/to/update_software.sh   # every 6th hour
0 0 1 * *   /path/to/scripts/run_scripts.sh   # midnight, first of the month
0 0 * * 0   /path/to/scripts/clean_database.sh   # midnight every Sunday
```

### Systemd vs. Cron
Both automate task execution; the difference is setup mechanics. Systemd needs a timer + service unit pair telling the OS when to run something; cron needs a single `crontab` entry telling the cron daemon when to fire.
