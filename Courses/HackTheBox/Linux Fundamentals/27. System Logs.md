Linux system logs record system and application activity, useful for monitoring, troubleshooting, and, for a pentester, spotting unauthorized logins, attempted attacks, cleartext credentials, or unusual file access. Reviewing logs after a security test also helps confirm whether an action triggered an intrusion-detection alert or system warning. Log hygiene matters too: correct log levels, rotation so files don't grow unbounded, and secure storage against tampering.

| Log type | Location | Contents |
| --- | --- | --- |
| Kernel logs | `/var/log/kern.log` | Hardware drivers, syscalls, kernel events; can reveal outdated/vulnerable drivers or crashes |
| System logs | `/var/log/syslog` | Service starts/stops, logins, reboots |
| Authentication logs | `/var/log/auth.log` | User authentication attempts, successful and failed |
| Application logs | e.g. `/var/log/apache2/error.log`, `/var/log/mysql/error.log` | Per-application activity, often including access/audit logs |
| Security logs | e.g. `/var/log/fail2ban.log`, `/var/log/ufw.log` | Security-tool-specific events |

**Access logs** (per-service, default locations below) record user/process activity: logins, file access, connections; **audit logs** record security-relevant events like config modifications.

| Service | Access log |
| --- | --- |
| Apache | `/var/log/apache2/access.log` |
| Nginx | `/var/log/nginx/access.log` |
| OpenSSH | `/var/log/auth.log` (Ubuntu) / `/var/log/secure` (CentOS/RHEL) |
| MySQL | `/var/log/mysql/mysql.log` |
| PostgreSQL | `/var/log/postgresql/postgresql-<version>-main.log` |
| Systemd | `/var/log/journal/` |

Logs are viewed and searched with the desktop's built-in log viewers or standard CLI tools: `tail`, **[[grep]]**, **[[sed]]**.
