### History
[[Unix]] was released by Ken Thompson and Dennis Ritchie at AT&T in 1970. Richard Stallman's GNU project (1983) aimed for a free Unix-like OS and produced the GPL, but lacked a working kernel until Linus Torvalds, a Finnish student, started the **Linux kernel** as a personal project in 1991. It's now over 23 million lines of C, licensed under the GNU GPLv2, and ships in 600+ distributions (Ubuntu, Debian, Fedora, RedHat, Linux Mint...). Android is Linux-kernel-based too, making Linux the most widely installed OS overall.

Linux is generally considered more secure and stable than Windows, with fewer viruses and frequent updates, though it can be harder for beginners and has fewer hardware drivers. HTB's interactive instances use **Pwnbox**, a customized [[Parrot OS]] (Debian-based, security/privacy-focused).

### Philosophy
Five core principles:
- **Everything is a file**: config for every service lives in one or more text files.
- **Small, single-purpose programs**: many focused tools, combinable.
- **Chaining programs together**: pipes and redirection let simple tools do complex work.
- **Avoid captive user interfaces**: Linux is built around the shell, giving the user more control than a locked-down GUI.
- **Configuration data stored in a text file**: e.g. */etc/passwd* holds every registered user.

### Components
| Component | Role |
| --- | --- |
| **[[Bootloader]]** | Guides the boot process (Parrot uses GRUB) |
| **[[Linux Kernel\|Kernel]]** | Core of the OS, manages hardware I/O resources |
| **[[Daemon]]s** | Background services (scheduling, printing, multimedia...) started after boot |
| **OS Shell** | The command-line interpreter between OS and user: [[bash]], Tcsh/Csh, Ksh, Zsh, Fish |
| **Graphics server** | "X"/"X-server" subsystem letting graphical programs run locally or remotely |
| **Window Manager** | GUI (GNOME, KDE, MATE, Unity, Cinnamon...) with file/web browsers etc. |
| **Utilities** | Programs performing specific functions for the user |

### Linux Architecture
Layered: **Hardware** (RAM, disk, CPU...) → **[[Linux Kernel\|Kernel]]** (virtualizes/controls hardware resources, isolates processes) → **Shell** (CLI to execute kernel functions) → **System Utility** (exposes the OS's functionality to the user).

### File System Hierarchy
![[Linux file system hierarchy diagram.png]]
Linux follows the **[[File System Hierarchy]]** Standard (FHS), a tree rooted at `/`:

| Path | Purpose |
| --- | --- |
| `/` | Root filesystem, everything needed to boot before other filesystems mount |
| `/bin` | Essential command binaries |
| `/boot` | Bootloader, kernel executable, boot files |
| `/dev` | Device files for hardware access |
| `/etc` | System and application configuration |
| `/home` | Per-user storage |
| `/lib` | Shared libraries required for boot |
| `/media` | External removable media mount points |
| `/mnt` | Temporary mount point for regular filesystems |
| `/opt` | Optional/third-party software |
| `/root` | Home directory for the root user |
| `/sbin` | System administration binaries |
| `/tmp` | Temporary files, generally cleared on boot |
| `/usr` | Executables, libraries, man pages |
| `/var` | Variable data: logs, mail, cron, web files |
