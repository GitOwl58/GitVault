A **package manager** installs, updates, and removes software distributed as packages: archives bundling binaries, config files, and dependency metadata. Typical responsibilities: package downloading, dependency resolution, a standard binary format, standard install locations, and quality control. If a package needs others not yet installed, the manager either warns the admin or fetches them automatically from a repository.

| Manager | Covers |
| --- | --- |
| **[[APT|dpkg]]** | Installs/removes/manages individual `.deb` packages directly |
| **[[APT|apt]]** | High-level Debian/Ubuntu front-end over dpkg, resolves dependencies automatically |
| `aptitude` | Alternative high-level interface to the same package system |
| `snap` | Sandboxed cross-distro packages ("snaps") |
| `gem` | Ruby's package manager (RubyGems) |
| `pip` | Python package installer, for packages not in the distro's own archive |
| `git` | Distributed version control, also commonly used to pull tools straight from source |

### Advanced Package Manager (APT)
Debian-based distros use **[[APT]]**. A `.deb` package is installed via `dpkg`; APT wraps this to resolve dependencies automatically, pulling from repositories defined in `/etc/apt/sources.list` (or `/etc/apt/sources.list.d/*.list`). Repositories are typically labelled stable, testing, or unstable.

- `apt-cache search <term>`: search the local package cache (e.g. for Impacket-related packages).
- `apt-cache show <package>`: view a package's metadata (version, dependencies, size...).
- `apt list --installed`: list every installed package.
- `sudo apt install <package> -y`: install, auto-confirming prompts.

### Git
`git clone <url> <destination>` pulls a project's full source, e.g. cloning a tool like Nishang from GitHub for later use.

### DPKG
Packages can also be downloaded and installed individually rather than through a repository: `wget <url-to-a-.deb-file>` to fetch it, then `sudo dpkg -i <file>.deb` to install it directly.
