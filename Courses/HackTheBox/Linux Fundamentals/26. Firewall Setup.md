A **[[Firewall]]** controls and monitors traffic between network segments, filtering by rules, protocols, ports, and other criteria to keep out unauthorized access and threats. Linux's classic implementation, **[[iptables]]**, replaced the older ipchains/ipfwadm tools starting with the Linux 2.4 kernel (2000) and became the de facto standard; it's built on the kernel's **Netfilter** framework, which hooks into the traffic path to intercept and modify packets. Newer alternatives exist too: **nftables** (modern syntax, better performance, but not iptables-rule-compatible), **UFW** ("Uncomplicated Firewall", a simpler interface layered on iptables), and **FirewallD** (dynamic zones/services for complex setups).

### Iptables Components
| Component | Role |
| --- | --- |
| **Tables** | Categorize rules by purpose |
| **Chains** | Group rules applying to a specific traffic type |
| **Rules** | Define match criteria and the action to take |
| **Matches** | The criteria themselves (source/dest IP, port, protocol...) |
| **Targets** | The action for a matching packet |

### Tables
| Table | Purpose | Built-in chains |
| --- | --- | --- |
| `filter` | Filter traffic by IP/port/protocol | INPUT, OUTPUT, FORWARD |
| `nat` | Rewrite source/destination IPs | PREROUTING, POSTROUTING |
| `mangle` | Modify packet header fields | PREROUTING, OUTPUT, INPUT, FORWARD, POSTROUTING |
| `raw` | Special packet-processing options | PREROUTING, OUTPUT |

### Chains
Built-in chains come pre-created per table (see above). **User-defined chains** group related rules for easier management, e.g. all rules for a set of web servers, or all rules for port 80 traffic, and can be attached into any of the three main tables.

### Rules and Targets
A rule combines match criteria with a **target** (the action for matching packets), added with `-A <chain>`:
```
sudo iptables -A INPUT -p tcp --dport 22 -j ACCEPT
```

| Target | Action |
| --- | --- |
| ACCEPT | Let the packet through |
| DROP | Silently block it |
| REJECT | Block it and notify the sender |
| LOG | Log the packet |
| SNAT / DNAT | Rewrite source / destination IP (NAT) |
| MASQUERADE | Like SNAT, for a non-fixed source IP |
| REDIRECT | Send to another port/IP |
| MARK | Tag the packet for later routing decisions |

### Matches
| Option | Matches on |
| --- | --- |
| `-p`/`--protocol` | Protocol (tcp, udp, icmp...) |
| `--dport` / `--sport` | Destination / source port |
| `-s`/`--source`, `-d`/`--destination` | Source / destination IP |
| `-m state` | Connection state (NEW, ESTABLISHED, RELATED) |
| `-m multiport`, `-m tcp`, `-m udp`, `-m string`, `-m limit`, `-m conntrack`, `-m mark`, `-m mac`, `-m iprange` | Additional match extensions |

Example: `sudo iptables -A INPUT -p tcp -m tcp --dport 80 -j ACCEPT` accepts incoming TCP on port 80.
