### Which
`which <program>` returns the path to the executable that would run for a given command (or nothing if it isn't installed), useful for quickly checking whether tools like curl, netcat, wget, python, or gcc are available on a target.

### Find
`find <location> <options>` searches the filesystem live and supports rich filtering: type, name pattern, owner, size, modification date, and running a command on each result. Example:

```
find / -type f -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null
```

| Option | Meaning |
| --- | --- |
| `-type f` | Only files (`d` for directories) |
| `-name *.conf` | Filename pattern |
| `-user root` | Owned by root |
| `-size +20k` | Larger than 20 KiB |
| `-newermt 2020-03-03` | Modified after this date |
| `-exec ls -al {} \;` | Run a command on each result, `{}` as a placeholder |
| `2>/dev/null` | Discard STDERR (not a `find` option itself, see [[File Descriptor]]) |

### Locate
`locate` searches a prebuilt local database instead of walking the live filesystem, so it's much faster than `find` but has fewer filter options and needs the database refreshed first with `sudo updatedb`. Which tool to reach for depends on what's being searched for: broad, fast lookups favor `locate`; precise, filtered ones favor `find`.
