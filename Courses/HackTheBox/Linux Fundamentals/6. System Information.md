Common tools for learning about a Linux system, its processes, network config, users, and settings; most installed by default:

| Tool | Purpose |
| --- | --- |
| `whoami` | Current username |
| `id` | Current user's UID, GID, and group memberships |
| `hostname` | Prints/sets the host's name |
| `uname` | OS name and system hardware info |
| `pwd` | Current working directory |
| `ifconfig` / `ip` | View/configure network interfaces |
| `netstat` / `ss` | Network status / socket inspection |
| `ps` | Process status |
| `who` | Logged-in users |
| `env` | Environment variables |
| `lsblk` | Block devices |
| `lsusb` | USB devices |
| `lsof` | Open files |
| `lspci` | PCI devices |

### Id
`id` expands on `whoami`, printing effective group membership and IDs, useful for a pentester or sysadmin auditing what a user can do. A non-standard group (e.g. a custom `hackthebox` group) is worth noting; membership in `adm` means the user can read `/var/log`; membership in `sudo` means the user can run some or all commands as root.

### Uname
`uname -a` prints kernel name, hostname, kernel release, kernel version, hardware, and OS in one line, e.g. `Linux box 4.15.0-99-generic #100-Ubuntu SMP ... x86_64 GNU/Linux`. `uname -r` alone gives just the kernel release, handy for quickly searching "4.15.0-99-generic exploit" to check for known kernel vulnerabilities. Studying each tool's man page in depth pays off later for privilege-escalation reconnaissance.

### Logging In via SSH
**[[SSH]]** lets us execute commands on remote hosts without a GUI, making it lightweight and efficient: the standard way most Linux servers are administered remotely, and the connection method used throughout HTB's Linux modules: `ssh [username]@[IP address]`.
