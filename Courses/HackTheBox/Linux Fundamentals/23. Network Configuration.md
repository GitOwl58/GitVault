Configuring and managing network settings is a core pentesting skill: setting up test environments, controlling traffic, and finding/exploiting vulnerabilities all depend on understanding Linux's network stack: interfaces, IP addressing, DNS, DHCP, and the access-control layer sitting in front of it.

### Configuring Network Interfaces
`ifconfig` is the older tool for viewing/configuring interfaces (IP, netmask, status); it's deprecated in favor of `ip`, though still widely present. `ifconfig` / `ip addr` show interface details; `sudo ifconfig eth0 up` or `sudo ip link set eth0 up` activates an interface; `sudo ifconfig eth0 192.168.1.2` assigns an IP; `sudo ifconfig eth0 netmask 255.255.255.0` sets a netmask; `sudo route add default gw 192.168.1.1 eth0` sets the default gateway.

DNS servers for the current session go in `/etc/resolv.conf` (`nameserver 8.8.8.8`), but this doesn't survive a reboot on its own. For persistent settings, `/etc/network/interfaces` defines static config:
```
auto eth0
iface eth0 inet static
address 192.168.1.2
netmask 255.255.255.0
gateway 192.168.1.1
dns-nameservers 8.8.8.8 8.8.4.4
```
`sudo systemctl restart networking` applies changes.

### Network Access Control
Network Access Control (NAC) ensures only authorized, compliant devices reach the network. Three enforcement models:

| Model | Approach |
| --- | --- |
| **DAC** (Discretionary) | Resource owners decide who gets access and what they can do with it |
| **MAC** (Mandatory) | Access is gated by matching security labels/clearances (resource vs. requester); common in military/finance/healthcare systems |
| **RBAC** (Role-based) | Permissions attach to roles, not individuals; scales well in large organizations |

### Monitoring
Capturing and analyzing traffic surfaces security threats and suspicious behavior, e.g. catching credentials sent over an unencrypted FTP login. Deeper traffic-analysis tooling (**[[Wireshark]]**, tshark, Tcpdump) is covered separately.

### Troubleshooting
| Tool | Purpose |
| --- | --- |
| `ping <host>` | Connectivity + round-trip time via ICMP |
| `traceroute <host>` | Path/hop-by-hop route to a host, via increasing TTL |
| `netstat -a` | Active connections and listening ports |
| Tcpdump / Wireshark / Nmap | Deeper traffic capture and network enumeration |

Common issues encountered during a pentest: connectivity problems, DNS resolution failures, packet loss, and general performance issues; causes range from misconfigured firewalls/routers and bad DNS records to outdated hardware or unpatched software.

### Hardening
Three complementary mechanisms:

| Mechanism | Type | Notes |
| --- | --- | --- |
| **SELinux** | MAC, kernel-integrated | Fine-grained policy enforcing access per process/file; more complex to configure |
| **AppArmor** | MAC, Linux Security Module | Uses per-application profiles instead of kernel-wide policy; simpler than SELinux but less granular |
| **TCP Wrappers** | Host-based network ACL | Restricts service access by client IP, via `/etc/hosts.allow` (grant) and `/etc/hosts.deny` (deny); not a firewall replacement, since it only controls services, not ports |

All three reduce unauthorized access and data-breach risk and are readily available on most distros. `/etc/hosts.allow`/`/etc/hosts.deny` rules are evaluated in order, first match wins.
