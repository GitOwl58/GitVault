Services split into internal (required at startup, often hardware-related) and user-installed (typically server software). Background services are **[[Daemon]]s**, often named with a trailing `d` (`sshd`, `systemd`). Most distros now use **[[systemd]]** as the init process (always PID 1), which starts/stops/monitors other services; every process gets a PID, viewable under `/proc/`, and may have a parent process ID (PPID) if spawned by another.

### Systemctl
- `systemctl start <service>`: start a service now.
- `systemctl status <service>`: check whether it's running and see recent log lines.
- `systemctl enable <service>`: link it into the SysV startup scripts so it runs after reboot.
- `systemctl list-units --type=service`: list all services and their state.
- `journalctl -u <service>.service --no-pager`: view a service's logs, useful when it fails to start.
- `ps -aux | grep <name>`: confirm a service's process is actually running.

### Kill a Process
A process is Running, Waiting, Stopped, or Zombie (terminated but still has a process-table entry). Interacting with one means sending it a signal, listed via `kill -l`. Most used:

| Signal | Meaning |
| --- | --- |
| SIGHUP (1) | Sent when the controlling terminal closes |
| SIGINT (2) | **[CTRL]+[C]**: interrupt |
| SIGQUIT (3) | **[CTRL]+[D]**: quit |
| SIGKILL (9) | Immediate kill, no cleanup |
| SIGTERM (15) | Request graceful termination |
| SIGSTOP (19) | Stop the process; cannot be caught/handled |
| SIGTSTP (20) | **[CTRL]+[Z]**: suspend, catchable, resumable |

`kill -9 <PID>` force-kills a frozen process.

### Background / Foreground a Process
**[CTRL]+[Z]** suspends the foreground process (sends SIGTSTP); `jobs` lists background/suspended jobs; `bg` resumes a suspended job in the background; appending `&` to a command starts it backgrounded from the outset; `fg <job ID>` brings a background job back to the foreground.

### Execute Multiple Commands
Three separators, differing in error handling:
- `;`: runs each command regardless of whether previous ones failed.
- `&&`: stops the chain the moment one command fails.
- `|`: pipes STDOUT from one command into the next (see [[File Descriptor]]).
